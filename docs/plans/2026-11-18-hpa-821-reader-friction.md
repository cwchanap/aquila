A signed-out first-time player can see the entire passage and action, reveal typing without waiting, find a speed setting in every reader mode, see honest loading and local bookmarks, revisit read scenes, and use menu controls. Preserve existing story graph, UI locale, assets, audio, URL, progress, and route choice semantics.

## Architecture and UX decisions

### A. Shared typewriter speed and Reveal control

- Keep the existing two-signal index/scene state machines in `NovelReader.svelte`, `VisualNovelReader.svelte` and `MobileNovelReader.svelte`. Do not extract/rewrite them. Retain `getReaderAdvanceDecision`'s `skip`, sceneVersion cancellation and existing audio/navigation effects.
- Update only shared `apps/web/src/lib/typewriter.ts` from constant `speed` to `delay: () => number`. Read delay each tick; 0 emits the full text and completes **without timers**. Check cancellation and skip first. Changing speed mid-line affects the next tick; Instant finishes then, with no separate reveal/restart-on-setting-change logic.
- Add `apps/web/src/lib/reader-typing-speed.ts` with browser-local read/write and pure `resolveTypingDelay(pref, prefersReducedMotion)`, matching `reader-furigana.ts`. Unset is a real preference value: normal-motion unset = **Fast 10ms**, reduced-motion unset = **Instant 0ms**; explicit Instant = 0ms, Fast = 10ms, Normal = 30ms. Explicit selection overrides the reduced-motion default. Storage failures act as unset. No account sync/schema.
- `ReaderShell` owns speed preference plus a **new `(prefers-reduced-motion: reduce)` listener in the shell** (it currently watches only the mobile breakpoint) and passes one reactive `typingDelay` prop into all three leaves. Each leaf passes `() => typingDelay` to `typeText`; **standalone leaf props default to 30ms** for direct-render tests while ReaderShell supplies 10ms/0ms defaults. Update timer tests only where the effective delay intentionally changes. During typing, show a labeled **Reveal text** button in the established progression slot, using the existing skip branch. A first gesture reveals the complete passage, not the next line or a route choice; a subsequent gesture advances. Ensure ruby/secondary line appears on completion and audio/SFX do not duplicate.
- Build one compact-capable `TypewriterSpeedPicker.svelte` (parallel to `SecondLanguagePicker`), with localized labels and native pressed buttons. Mount in `ReaderSettingsMenu` AND in phone text-mode `MobileNovelReader`'s existing options panel. **Do not gate phone options on secondLanguageChoices.length > 0**; render the speed picker even for text-only stories. The phone button's accessible label must describe general *reading settings*, rather than only second language. Keep second-language/furigana subcontrols conditional. Use en/zh/ja reader translations.

### B. Stable dialogue geometry, without JS resize/scroll state

- **Visual:** keep `--dialogue-box-height` as the **minimum** feeding portrait bottom/height CSS; change box to `height:auto; min-height:var(--dialogue-box-height)` with a safe-viewport `max-height`. Long boxes can overlay portraits, not reposition them while typing. Preserve the existing footer grid row outside the scroll body.
- Prevent animation-induced growth: **only while `isTyping`**, reserve the **full primary and secondary line** (including ruby) invisibly in the same grid cell using `visibility:hidden`, `aria-hidden="true"` and `pointer-events:none`. Overlay visible typing text; switch to actual full text at completion without height jump. Hidden reserve is never announced or interactive.
- **Mobile text:** change h-52/h-64 to content-driven `min-height` plus safe-viewport `max-height`; use the same full-text reserve so bilingual reveal does not shift the panel. Under **`@media (max-height:31rem) and (orientation:landscape)`**, reduce/disable the normal height floor (to about 7.6rem or zero): CSS `min-height` overrides `max-height`, and on 844×390 the old 16rem floor plus the back row and padding collides with the top menu. Keep last-line action outside text scroller and out of the top control's bounds.
- **Mobile footer and chrome:** keep one constant `min-h-11 flex items-center justify-end` footer row for typing **Reveal**, non-final **▼**, and final **Choose/Continue**. Wire Reveal with `stopPropagation`, matching the existing terminal button, so the full-screen tap layer cannot also advance. Cap expanded mobile chrome/options to `max-h-[calc(100dvh-2rem)] overflow-y-auto` so all settings remain reachable in short landscape.
- **Desktop text:** move Continue/Choose/Reveal **outside** its existing max-h-[70vh] transcript scroller. Do not create another footer system.
- Add a CSS-only scroll affordance in `apps/web/src/styles/global.css` on the three scroll regions, **blended with their existing translucent glass backgrounds**. An opaque `background-attachment:local` cover may produce a solid padding seam; a translucent cover may leave a phantom shadow. Select a compatible inset/edge/mask treatment and validate the result in MCP screenshots. No ResizeObserver or manual scroll-follow state. On overflow the text must really scroll; on fit the cue must not suggest hidden text.
- Layout is a **real browser** concern, not a Vitest measurement: one committed Playwright spec checks representative long Latin/CJK bilingual passages at 1440×900, 390×844, and 844×390. Assert actions visible/clickable, no overlay collisions, no jitter during typing/reveal, and either no overflow (`scrollHeight <= clientHeight`) or **actual scrollability** (`scrollTop` advances). Computed background CSS does not indicate overflow: inspect the cue via MCP screenshots rather than asserting its visibility from `getComputedStyle`.

### C. SSR loading and bookmark state

- `apps/web/src/pages/[locale]/reader.astro` should put localized `reader.loadingStory` in server-rendered `#reader-container`, using the same dark status block / `role="status"` as `ReaderShell.loadSurface`. `ReaderManager` already replaces server children on mount; preserve loading/error/retry, active-reader overlay, URL and deep-link behavior. **Do not add an open-ended TTFB/network trace investigation**; if the initial HTML itself is still slow, file a separate measured performance issue.
- `apps/web/src/pages/[locale]/bookmarks.astro` calls `getSessionUser` with `SESSION_LOOKUP_TIMEOUT_MS` (1500ms) and derives `authStateFromSession`, like reader.astro. Embed `data-auth-state` in bookmarks container; render localized `bookmarks.loading` in the initial server HTML instead of an empty element. Retain existing degraded-auth banner. Extract the tiny `authStateFromAttr` parser from `reader-bootstrap.ts` into a **client-safe pure helper** such as `lib/auth-state-attr.ts`, reused by bookmarks and reader bootstrap. Import `AuthState` type-only from `auth-utils.ts` rather than runtime-importing the server auth utility into the browser; server Astro retains `authStateFromSession`.
- `BookmarksManager` accepts `signed-in | signed-out | unavailable` from server, defaulting the optional constructor argument to **`unavailable`** so existing unit tests still exercise fetching. Render local cards **before** any optional cloud call. For known signed-out, **skip `/api/bookmarks`** and show a genuine local/login state. Add an explicit **`cloudLoading` flag** so signed-in shows local cards and a Cloud section loading label rather than prematurely flashing `No bookmarks yet` / `Start Reading`; unavailable with zero local cards must also keep a loading surface rather than blank content. For unavailable, keep the fetch/recovery path; don't claim signed out without a real 401. Preserve local cards on 500/error. Remove redundant `initializeUI`.
- Tests cover SSR before hydration, replacement on mount, direct-link retry, signed-out no-fetch, delayed signed-in cloud and degraded/failed cloud. Existing **`packages/e2e/tests/bookmarks.spec.ts` cloud-500 tests intercept an unauthenticated page** and will stop reaching the API once signed-out skips fetch; update them to exercise `signed-in`/`unavailable` **SSR auth-state fixtures** (no OAuth bypass) and add signed-out no-fetch. Add unit checks for cloudLoading/500/empty states. No cloud API or backend change.

### D. Session History recorded as scene segments

- Add pure `apps/web/src/lib/reader-history.ts` capturing **only** `{sceneId,lastIndex}` when leaving a scene within the same story (max **50 segments**). Use **chronological append, never deduplication by sceneId**: `act1 → act2 → act1` displays the first act1 visit, then act2, then the current act1 visit. Avoid repeat appends from effect re-runs without a real exit. **Ignore empty story/scene IDs and incomplete/loading/error state**, and reset instead of appending across story changes. The view adds the current scene's existing `dialogue.slice(0,dialogueIndex+1)`. No per-line copies, permanent events, or invented branch history.
- Build display lines on demand from `ReaderShell.getSceneDialogue` and current `secondContent.dialogue[sceneId]` via `alignSecondDialogue`, `resolveCharacterName` and `actLabel(extractActName(...))`. Drop segments for missing scenes. The current second language, furigana and translated story payload determine display, so toggles do not leave stale snapshots. **Clear on story change**, not on mode switch or primary-locale change.
- **ReaderShell builds `historyLines`** using its existing scene/secondary-language access. Pass an **optional `historyLines` prop** to `VisualNovelReader` and `MobileNovelReader`, with a **current-scene-only fallback when undefined** so existing standalone leaf components/tests continue working. Both backlogs consume the shared `lines` shape (from MobileBacklogSheet, extended with optional act/scene separators); `VisualBacklog` no longer slices only the active scene. Preserve deep-link and focus-return behavior. Pure Vitest coverage for chronological repeated visits, bounds, empty/loading identities, story changes, missing payload, mode and locale changes; one end-to-end visited-act/revisit scenario.

### E. Small menu fixes; Acts guarded by regression

- Move the three existing MainMenu locale links into native `<details><summary>` showing the active endonym **with an accessible language-switcher label**. Keep the links and `handleLanguageClick` persistence; no extra state, outside-click handler or picker library. Since the active language now appears in summary **and** a hidden link, update `MainMenu.test.ts` to use role/accessible visibility rather than ambiguous `getByText('English')`.
- Remove 📖 from **nine** shared translation values: `menu.bookmarks`, `bookmarks.title` and `reader.bookmark` in en/zh/ja. This corrects aria-labels and HTML title too. Add an existing Lucide book icon next to plain text at the three rendered entry points: `MainMenu.svelte`, `ReaderSettingsMenu.svelte`, `bookmarks.astro`. Update affected assertions in `ReaderSettingsMenu.test.ts`, `packages/e2e/tests/story-select.spec.ts`, `packages/e2e/tests/utils.ts`, and `packages/e2e/tests/visual-novel-deployed.spec.ts`, plus tab-title checks. No new art/fonts; preserve unrelated desktop-used translations.
- Add an Acts navigation regression for an actually visited previous act and an unread branch. Repair `buildChapterData` / `visibleSceneIds` only if it fails; never reveal future branches by default.

## Single-PR implementation order

Each step is a small **commit with its tests**, not another PR. Recheck latest main before starting.

1. Run current targeted tests and write the **Acts regression** first. Keep existing Crossroads/My Progress checks; skip a large baseline screenshot survey.
2. **Menu/emoji**: native details and plain accessible labels/icons; UI/translation tests.
3. **Loading/bookmarks**: bounded auth, client-safe attr parser, `cloudLoading`, immediate local render and truthful SSR placeholders; adapt cloud-500 E2E states and add signed-out no-fetch.
4. **Typing**: shared dynamic delay, preference helper, **shell reduced-motion listener**, Reveal controls and shared picker (including phone text mode without translations), stable mobile footer, and targeted unit/component/E2E adjustments.
5. **History**: chronological segment helper, guarded identities, optional leaf `historyLines` fallback, both sheets, visited-act and revisit E2E.
6. **Layout**: stable visual/mobile boxes with short-landscape minimum override, hidden full-line reserve only during typing, desktop action outside scroller, translucent-safe CSS cue; browser scrollability/geometry tests and focused MCP screenshots.
7. **Final gate**: lint, stories, web build, unit tests and committed `.spec.ts` via `bun --filter e2e test:e2e ...` (through an MCP-capable command runner if available). **Separately perform the E2E UI journey and automated screenshot/visual acceptance using browser/Playwright MCP.** Do not claim browser MCP itself executes Playwright `.spec.ts`; report both gates accurately. Attach evidence to **PR #140** and address reviewer feedback here. No other implementation PR.

## Risks and safeguards

1. **Portrait/landscape geometry:** visual height variable positions portraits; mobile min-height overrides max-height in short landscape. Retain visual minimum, reduce mobile landscape floor, fix footer row height, and cap expanded chrome.
2. **Unreachable phone control:** the phone text reader has no ReaderSettingsMenu, and its old language options disappear for unilingual stories. Always make speed reachable there.
3. **Duplicated timing:** centralize delay in `typeText` and pass one shell prop; retain already-tested leaf lifecycle state machines.
4. **Fast-default behavior:** changing global default from 30 to 10ms may surprise readers; make 10/30/Instant explicit, honor reduced-motion unset, and test.
5. **SSR/bookmarks handoff:** no duplicate placeholder, premature empty-cloud flash, blank cloud-loading state or cloud-only block of local bookmarks. Update signed-out cloud-error tests for the new no-fetch behavior.
6. **History/spoilers:** chronological exited scenes only, no empty/loading IDs or unseen branches, and direct-leaf fallback remains.
7. **Glass scroll cues:** no opaque rectangular seam on translucent panels; Playwright proves real scrolling, MCP screenshot proves cue aesthetics.

## Non-goals

No new art/SFX (if ever needed, create a separate art-generation ticket), no backend/API/storage migration, no TTFB project, no compiler/story edits, no extra UI/layout library, no complex scroll tracker, no compatibility layer and no global state framework. Keep the solution small and maintainable.
