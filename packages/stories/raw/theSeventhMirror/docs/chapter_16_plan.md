> `TOKYO-7` 的用途究竟是什麼？

本章的主要突破為：

- 澪沿著 Chapter 15 找到的三個合法追查入口，分別取得三份不同性質的替代文件；

本章的情感與主題核心是：

> 澪一直以為「不要救東京」裡的東京是一座城市。

> 她只知道——千田死前說的那句話，從來不是關於一座城市。

# 3. 全域一致性鎖定

## 3.1 `TOKYO-7` 用途分類

本章可以證明：

- 議會審查摘要（年度公開版）將 `TOKYO-7` 歸入「情境／同步用途設定」分類，而非「地域配置」分類；
- 該分類來自議會監督程序中的公開摘要，不是 TKS 自述；
- 分類欄位引用了「設定檔目的記述書」的版本號，但未引用正文。

本章不能證明：

- 「情境／同步用途」等於東京方案；
- 「情境」指記憶同步、外星訊號或全球共同記憶；
- `TOKYO-7` 的同步對象是孩子或受試者；
- `-7` 等於 G07 或第七日。

普通解釋仍成立：

- 「情境用途設定」可能指特定災害情境的預設配置；
- 「同步用途」可能指多通道呈現順序驗證（與 Chapter 14 的 `+7000ms` 一致）；
- 議會摘要的分類可能只是行政歸檔用語，不代表實際功能。

## 3.2 「東京不指涉地名」正式文件語句

定稿語句：

> **本設定檔之「東京」為情境識別名，不指涉地理名稱。**

來源：舊驗收說明書（已退役設備解密範圍）。該文件因對應設備已退役、金鑰與端點表已刪除，而被列入解密範圍。

本章可以證明：

- 這是一份正式驗收文件中的句子，不是研修教材、不是私人記憶、不是推測；
- 該句出現在「設定檔命名原則」章節，用於說明命名規則；
- 該句的上下文是命名規範，不是功能描述——它說明「東京」這個詞的指涉規則，沒有說明這個情境是什麼。

本章不能證明：

- 「情境識別名」具體指什麼情境；
- 這個情境與孩子、記憶、外星訊號有關；
- `TOKYO-7` 就是東京方案；
- 千田遺言「不要救東京」指的就是這個設定檔（雖然高度吻合）。

## 3.3 公開名與內部用途名分離

監督委員會引用目錄顯示：

- `TOKYO` 是對外公開文件使用的設定檔名稱；
- `TOKYO-7` 是內部維護別名，用於實際運用環境與研修教材；
- 兩者刻意分開維護，理由欄寫明：

> **避免公開文件洩露情境屬性。**

本章可以證明：

- 公開名與內部用途名的分離是刻意制度設計，不是偶然的版本差異；
- 分離理由涉及「情境屬性」——也就是說，公開名之所以用「東京」這個地名樣式的詞，是為了不讓外界從公開文件推測出真正的用途屬性。

本章不能證明：

- 「情境屬性」的具體內容；
- 這套分離制度是為了掩蓋犯罪，還是出於普通的公共安全保密慣例；
- TKS 法務是否知道分離的真正理由。

## 3.4 三個合法入口的證據分工

三份文件不是單一來源：

| 文件 | 來源性質 | 能證明 | 不能證明 |
|---|---|---|---|
| 議會審查摘要（年度公開版） | 議會監督程序公開摘要 | `TOKYO-7` 被歸入情境／同步用途分類 | 分類的具體功能 |
| 舊驗收說明書（已退役設備解密範圍） | 退役設備驗收文件解密版 | 「東京」為情境識別名，不指涉地理名稱 | 情境的具體內容 |
| 監督委員會引用目錄 | 監督委員會公開引用目錄 | 公開名與內部用途名刻意分離，理由為避免洩露情境屬性 | 分離制度的真正動機 |

三份文件分別來自議會監督、退役設備驗收解密、監督委員會引用——三個不同的制度來源，避免整條證據鏈只依賴 TKS 或單一主管單位。

# 5. 本章必須完成的五項成果

## 成果一：`TOKYO-7` 被歸入情境／同步用途設定

議會審查摘要（年度公開版）的分類表顯示：

| 欄位 | 內容 |
|---|---|
| 設定檔名稱 | `TOKYO-7` |
| 分類 | **情境／同步用途設定** |
| 對照組 | 一般地域配置（例如 `OSAKA`、`NAGOYA` 類） |
| 引用文件 | 設定檔目的記述書（舊版） |
| 監督狀態 | 列管中 |

必須有對照組：摘要表中同時列出其他被歸為「一般地域配置」的設定檔，讓「情境／同步用途」這個分類成為有意義的對比，而不是孤立標籤。

這能證明：

- `TOKYO-7` 不是普通的地域配置；
- 它屬於一種需要另外分類的用途；
- 議會監督程序知道這個分類，且將其列管。

仍不能證明：

- 「情境／同步用途」的具體功能；
- 該分類與孩子、記憶或外星訊號的關係。

## 成果二：找到「東京不指涉地名」的正式文件語句

舊驗收說明書（已退役設備解密範圍）的「設定檔命名原則」章節出現：

> **本設定檔之「東京」為情境識別名，不指涉地理名稱。**

該句的上下文：

- 出現在命名原則章節，不是功能描述章節；
- 用於向驗收人員說明為什麼設定檔叫「東京」卻不綁定地理區域；
- 同一章節列出其他命名規則（例如資產序號、內容標籤、版本編號），「東京」這條只是其中一條。

這能證明：

- 「東京」這個名稱在正式文件中明確不指涉地名；
- 這不是澪的推測、不是循環記憶、不是研修教材的模糊暗示，而是驗收文件的正式語句；
- 千田遺言「不要救東京」裡的「東京」，高度可能指的就是這個不指涉地名的設定檔。

仍不能證明：

- 「情境識別名」具體指什麼情境；
- 千田遺言確實指這個設定檔（仍是高度吻合，不是證明）。

## 成果三：公開名與內部用途名刻意分離

監督委員會引用目錄顯示：

| 欄位 | 內容 |
|---|---|
| 公開名稱 | `TOKYO` |
| 內部維護別名 | `TOKYO-7` |
| 分離狀態 | 刻意分開維護 |
| 分離理由 | **避免公開文件洩露情境屬性** |
| 核准層級 | 危機運用整合室 |

這能證明：

- 公開名與內部用途名的分離是制度設計，不是版本混亂；
- 分離理由直接提到「情境屬性」——表示這套設定有一種不願讓公開文件露露的屬性；
- 核准層級是「危機運用整合室」（與 Chapter 15 設定檔目的記述書的主管單位一致）。

仍不能證明：

- 「情境屬性」的具體內容；
- 分離制度是為了掩蓋犯罪，還是普通保密慣例；
- 危機運用整合室是否知道完整真相。

## 成果四：三個合法入口的證據鏈分工

三份文件分別來自三個獨立制度來源（議會監督、退役驗收解密、監督委員會引用），且彼此印證：

- 議會摘要的分類 → 印證 `TOKYO-7` 不是地域配置；
- 退役驗收說明書的命名原則 → 印證「東京」不指涉地名；
- 監督委員會引用目錄 → 印證公開名與內部用途名刻意分離，且理由與情境屬性有關。

三者拼合，才讓「東京不是城市」這個第四日主題正式落地——任何一份單獨都不夠。

# 8. 誤導與普通解釋

本章必須保留以下普通解釋：

| 線索 | 普通解釋 |
|---|---|
| `TOKYO-7` 歸入情境／同步用途 | 特定災害情境的預設配置（例如灣岸防災同步試驗），與 Chapter 14 的 `+7000ms` 一致 |
| 「東京」為情境識別名 | 命名規範用語，避免驗收人員誤以為設定檔綁定地理區域 |
| 公開名與內部用途名分離 | 公共安全系統常見的保密慣例，避免公開文件暴露系統內部結構 |
| 「避免洩露情境屬性」 | 普通的防濫用理由，不代表情境屬性本身違法 |
| TKS 法務收窄小野寺說法 | 公司面對刑事案件與媒體詢問的正常法務反應 |
| TKS 對外口徑與議會分類不一致 | 對外口徑簡化為「一般城市設定檔」，議會監督用較精確分類，兩者可能只是詳細程度不同 |

讀者可以合理懷疑：

- `TOKYO-7` 就是東京方案；
- 「情境」指記憶同步；
- 公開名的設計是為了掩蓋犯罪；
- TKS 法務正在說謊；
- 千田遺言指的就是這個設定檔。

但本章不能把任何一項直接確定。「東京不是城市」確定了；「東京是什麼」仍未確定。
